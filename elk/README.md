# elk/ — Kibana dashboards for the capacity suite

Ships the suite's analytics (observed daily series, forecasts, fits,
anomalies, alerts) from Oracle into Elasticsearch through the same Filebeat
and Logstash path the rest of the Oracle telemetry uses, and installs three
Kibana dashboards on top. Everything in Oracle stays read-only; the only thing
that runs against the database is `SELECT` through SQL*Plus, and nothing on
the database host talks to Elasticsearch.

```
DB host (oracle user)
  elk/export.sh                 runs elk/export_capacity.sql through SQL*Plus,
     │                          validates every document against the mapping,
     │                          appends generated/awrcap-<source>-<day>.ndjson
     ▼
  Filebeat  (elk/filebeat/awrcap.yml, a filestream input in inputs.d/)
     │  Beats protocol, mTLS
     ▼
Logstash   elk/logstash/oracle_capacity.conf next to elk_db_automation's
     │     oracle.conf: prunes to the contract, writes with the exporter's id
     ▼
Elasticsearch  index awrcap-capacity  (mapping: elk/elasticsearch/index-template.json)
     ▼
Kibana   data view awrcap-capacity-dataview + three Lens dashboards
         (generated by elk/kibana/build_*.py, imported by elk/setup.sh)
```

## Documents

One plain index, five record types, all under the `cap.*` namespace. The
index is deliberately not a data stream: every document has a deterministic
`_id`, so a re-run overwrites instead of duplicating.

| `cap.record`  | one per                                    | `@timestamp`                    |
|---------------|--------------------------------------------|---------------------------------|
| `observation` | container × series × day                   | the day                         |
| `forecast`    | container × series × method × horizon      | last observed day + horizon     |
| `fit`         | container × series × export day            | export day                      |
| `anomaly`     | flagged event (growth, CPU, level shift)   | event day                       |
| `alert`       | `CAPR_ALERTS` row × export day             | export day (`cap.obs_day` = the day it refers to) |

`cap.kind` is `TBSPC`, `CPU` or `SERIES`; `cap.series` is the tablespace,
CPU metric or workload series name; `cap.db` is the display label the
reports use (`DBNAME` or `DBNAME/PDBNAME`). An observation flagged by the
`CAPA_*` layer carries `cap.anomaly: true` plus `cap.z`, `cap.expected` and
`cap.threshold`, which is what the dashboards draw in red.

Forecast points are anchors (REGR at +0/+30/+90/+180/+365, ESM at +30);
Lens joins them with linear fitting. Because they lie in the future, the
dashboards default to a time range that ends after today.

## Install

Stack side, once, from a workstation that can reach Elasticsearch and Kibana
(`ES_URL`/`ES_USER`/`ES_PASSWORD`, `KIBANA_URL`/`KIBANA_USER`/`KIBANA_PASSWORD`,
defaults `http://localhost:9200`, `:5601`, `elastic`):

```bash
elk/setup.sh                                     # index template + data view + dashboards
cp elk/logstash/oracle_capacity.conf <logstash pipeline dir>/   # beside oracle.conf
docker compose restart logstash                  # or however that Logstash reloads
```

DB host side, as the Oracle owner, with the suite installed in the schema you
export from and Filebeat deployed per `elk_db_automation` (the
`inputs.d/` directory is hot-reloaded, so no restart):

```bash
cp elk/filebeat/awrcap.yml /u01/app/oracle/filebeat/inputs.d/ && chmod 600 /u01/app/oracle/filebeat/inputs.d/awrcap.yml
elk/export.sh --sid cdb1                                  # local-mode install in CDB$ROOT
elk/export.sh --sid cdb1 --container PDB1 --schema CAPDEMO   # a fixture/demo schema in a PDB
```

Run `export.sh` daily (cron, or a DBMS_SCHEDULER external job). It appends to
one file per source and day under Filebeat's `generated/` directory, deletes
files older than `--retention-days` (7), and refuses to write anything that
does not match the mapping. `--stdout` prints the validated NDJSON instead.
The `--source` label keys every document; keep it stable per database.

## Dashboards

| id | title | answers |
|----|-------|---------|
| `awrcap-dashboard-tablespaces` | AWR Capacity - Tablespaces | which tablespaces run out first, how fast they grow, where growth jumped |
| `awrcap-dashboard-cpu-series` | AWR Capacity - CPU and workload series | host CPU vs the saturation line, DB CPU level shifts, sessions/processes vs their limits |
| `awrcap-dashboard-fleet-anomalies` | AWR Capacity - Fleet anomalies | every flagged day across every database, newest first |

Anomalies are highlighted the same way everywhere: a red bar under the
observed line on the day the `CAPA_*` layer flagged, and a row in the
anomaly table with the one-line explanation (`cap.message`). Alerts
(`CAPR_ALERTS`) appear as a compact table on every dashboard.

Open them at `http://<kibana>/app/dashboards#/view/<id>`.

## Regenerating the dashboards

The `.ndjson` files under `elk/kibana/dashboards/` are generated; edit the
`build_*.py` builder, not the output. `elk/setup.sh` rebuilds before it
imports. All panel ids are md5-derived from stable names, so a rebuild is
byte-identical unless the builder changed.

## Adding a field

The mapping is `dynamic: strict`: `export.sh` refuses a document with an
unmapped field before Filebeat sees it, and Elasticsearch would reject it
anyway. Add the field to `elk/elasticsearch/index-template.json` first, re-run
`elk/setup.sh` (it re-PUTs the template and updates the live mapping), then
emit it from `export_capacity.sql`. Fields Filebeat adds (`host.name`,
`labels.*`) are the only ones that bypass the exporter; the Logstash branch
prunes everything else.

## Notes and limits

- "Latest export" panels (KPI tiles, days-to-full and alert tables) read
  fit/alert documents stamped in the last two days. If `export.sh` stops
  running for longer than that, those panels go empty while the history
  charts keep working. Run it daily.
- Forecast points key on (series, method, horizon), so each run overwrites
  the previous run's points. A series whose forecast disappears (quality
  drops to INSUFFICIENT_HISTORY) keeps its last points until it comes back.
- The Logstash file must sort after `oracle.conf` in the pipeline directory
  (it does, `_` > `.`); its prune runs after that pipeline's common filters.
- A DB CPU level shift is dated at the start of its recent window
  (`shift_days`, default 7), the closest the `CAPA_CPU_SHIFT` view gets to the
  day the level moved. The window's last day is in `cap.obs_day`.
- Unfiltered XY charts draw every tablespace or container at once. Pick a
  database or series in the controls at the top to read a single line; the
  fleet anomaly table's drilldowns do that for you.
- Forecast lines are solid (Lens has no per-layer dash style); they carry a
  "Forecast" legend label and start at today.
- The fixture databases loaded here (ECOMPRD, FIXCDB) are the repo's demo and
  test fixtures re-anchored to the install day, so their last observed day is
  the day the fixture was installed, not a live AWR feed.
