Architecture

The swappable data source (the "seam")

One idea makes the whole thing portable — write the reporting once, swap where the data comes from underneath it.

Every calculation in this tool reads from a thin layer of six views prefixed CAPV_, shaped to look just like Oracle's AWR data dictionary. Nothing above them ever touches the real DBA_HIST_* tables directly. That single layer is the seam: to change where the data comes from, you swap one install file, and everything above it behaves identically — same math, same report, same numbers. It's the database equivalent of pointing a hostname at a different server.

Why this matters for testing. You can't insert fake rows into Oracle's real AWR tables, so there'd normally be no way to check the forecasts are correct. The seam solves that: point it at fixture mode — synthetic data whose exact answers are worked out on paper in advance — and confirm the tool reproduces them. Then point the very same code at real AWR (local mode) with confidence.

Architecture

Layer reference

What each layer is responsible for, and the non-obvious decisions baked into it.

CAPV_  — seam views

Six views re-present the AWR dictionary in a stable shape carrying (dbid, con_dbid). con_dbid is mandatory: TS# restarts at 0 per container, so SYSTEM in the root and in a PDB would collide without it. Block size rides on CAPV_TABLESPACE (populated for every tablespace); the datafile view is a fallback only, because DBA_HIST_DATAFILE is missing SYSTEM on stock 19c.

CAPD_  — daily series

Tablespace usage is a level, so each day keeps the last sample (KEEP (DENSE_RANK LAST ...)) and converts blocks→bytes. UNDO/TEMPORARY are excluded. CPU BUSY/IDLE are cumulative counters — consecutive snaps are differenced per instance, and any interval spanning a restart (startup_time changed) or showing a negative delta is dropped. Deltas expose day_gap so a multi-day AWR gap becomes a rate, not a false spike.

CAPF_  — Tier 1 forecasts

Ordinary least squares over day_n = day_dt − DATE '2020-01-01'. Two fits per series (a 90-day primary and a 28-day "recent"), giving an accel_ratio that flags accelerating growth. days_to_full = FLOOR((limit − cur_used)/slope). Quality is graded in priority order:

QualityCondition
INSUFFICIENT_HISTORYREGR_COUNT < min_train_days — too little AWR retention
FLATslope = 0. Note: REGR_R2 returns 1 for a flat series, not NULL, so flatness keys off the slope
LOW_CONFIDENCER² < r2_gate (default 0.60)
OKa trustworthy trend

CAPA_  — anomalies

Robust median + MAD, where MAD_σ = MEDIAN(|x − median|)·1.4826. Each view is a trailing-window self-join in two passes (median, then MAD about it), always excluding the current day so a spike can't inflate its own baseline. Tablespace anomalies work on the growth rate with a GREATEST(k·MAD, abs_floor_bytes) threshold, so a jump from an exactly-flat baseline still flags but sub-100 MiB/day wiggles never do. CPU anomalies baseline against the prior same weekdays, handling weekly seasonality deterministically. Every flag carries value, median, MAD·k threshold, and robust z for hand-verification.

Architecture

Two engines, side by side

A fully auditable baseline and a seasonality-aware second opinion.

Tier 1 · always on

Pure SQL — a straight trend line

Standard linear regression. Every forecast is just slope × days + starting point, and every anomaly is explained by its median and MAD — so you can check any number by hand. Nothing to train, nothing hidden.

Reaches: +30 / +90 / +180 / +365 days Needs: nothing beyond the views
Tier 2 · optional

OML ESM — exponential smoothing

One model per series via DBMS_DATA_MINING. Tablespaces use Holt (trend); CPU uses additive Winters (weekly seasonality). Shown against Tier 1 in section 6.

Reaches: +30 only — 19c hard-caps the horizon at 30 steps Needs: CREATE MINING MODEL
!

The 30-step cap is real. Oracle 19c rejects EXSM_PREDICTION_STEP above 30 at any series length (verified: 30 valid, 31 fails at 121/300/600 rows). So ESM forecasts only ever reach +30 days; +90/+180/+365 in CAPF_COMPARE come from Tier 1 alone. The package caps the step automatically.
