Testing

Two ways to try it. Track A proves every part of the suite against known answers with deterministic fixtures; Track B runs the exact same code against real AWR.

Run Track A first — it installs synthetic data whose exact answers are worked out in advance and confirms the tool reproduces them, failing loudly if any number is off. Then Track B points the identical code at your live AWR to confirm it installs and reports end-to-end on a real 19c CDB. Both tracks run on your own 19c test box.

Before you start

Two ways to try it, both on your 19c test box. Run Track A first — it proves every part of the tool against known answers; Track B then runs the exact same code against your real AWR.

Track A — recommended first

Fixture self-check

Install fixture mode (fake data) as CAPTEST in PDB1, then run the self-check script. This is how you "test everything yourself": it compares every result against a known-correct answer and fails loudly if any is off. No AWR history required.

Where: PDB1 · captest/<password> Proves: forecasts, anomalies, CPU guards, ESM Time: ~2 minutes
Track B — the real thing

Local smoke on cdb1

Install local mode as sysdba in CDB$ROOT and generate the report against live AWR. On a stock box expect INSUFFICIENT_HISTORY until you raise retention — which is itself the point: the report degrades loudly.

Walkthrough · Track A

Fixture self-check

Run the tool against fake data with known answers, and confirm forecasting, anomaly detection, the CPU-restart guard, and the optional Tier 2 model all produce exactly the right numbers — end to end, on your test box.

1

Sync the repo to the host

From the repo root on your workstation. The relative @@ includes need the tree present on the host; excluding reports/ avoids shipping old spools.

workstation · bashyou run
# from /home/db/github/awr_capacity_predictions
rsync -az --delete --exclude='.git/' --exclude='reports/' \
  ./ oracle@<host>:~/awr_capacity_predictions/ -e 'ssh -p <port>'
2

Connect as CAPTEST in PDB1, from the repo root

CAPTEST has CREATE TABLE/VIEW/TYPE/PROCEDURE and CREATE MINING MODEL — everything the fixtures, the install, and Tier 2 need.

test box · bashyou run
ssh -p <port> oracle@<host>
export ORACLE_SID=cdb1; export ORAENV_ASK=NO; . oraenv >/dev/null 2>&1
cd ~/awr_capacity_predictions
sqlplus captest/<password>@localhost:1521/pdb1.world
3

Load the fixtures

Creates and fills the CAP_FIXTURE_* tables with four fake tablespace growth patterns and one CPU pattern — every value hand-calculated, dated relative to today. The known-correct answers are stored alongside in CAP_FIXTURE_META, so the self-check reads them rather than working them out again.

SQL*Plus · captest@pdb1you run
SQL> @test/fixture_install.sql
outputexpect
Fixtures loaded: base=2026-03-08 restart=2026-05-07 spike=2026-06-26
  inj_tue=2026-07-01 Tue probe=2026-07-04 Sat
Fixtures installed.  Next: @install.sql (seam_mode=fixture), then test/run_test.sql
i

The four series: FIX_LINEAR (exactly 10 MiB/day), FIX_SPIKE (5 MiB/day + a one-time +2 GiB step), FIX_FLAT (constant), and FIX_GAP (60 MiB/day with a deliberate 3-day AWR gap). Plus a CPU counter series with a mid-run restart and an injected +30-point Tuesday. Dates will differ — they're anchored to today.

4

SQL> @install.sql

5

Run the Tier 1 self-check

Sixteen checks over the fake data — every result compared to its known-correct answer. It prints PASS/FAIL per check and exits with an error code on any failure, so you can wire it straight into CI or a monitoring job.

SQL> @test/run_test.sql
outputexpect

  PASS  LINEAR r2 > 0.999
  PASS  LINEAR days_to_full = 4990
  PASS  LINEAR quality = OK
  PASS  LINEAR anomaly count = 0
=== FIX_SPIKE anomaly ===

  PASS  SPIKE HIGH on spike day = 1
  PASS  SPIKE LOW count = 0

▸

What each block proves. Each fake series targets one behavior. LINEAR → the slope, R², and days_to_full=4990 land on the exact known answer. SPIKE → exactly one HIGH, on the spike day only. FLAT → graded FLAT, no false anomaly. GAP → the 4-day gap becomes a rate, so no phantom spike. CPU → the restart day is dropped, busy% is exactly 40 on a probe weekday, and only the injected Tuesday flags in the same-weekday view.

Run the Tier 2 (optional ML) self-check

outputexpect

  PASS  FIX_LINEAR model trained OK

All ML assertions passed.

8

Tear the fixtures down

Leaves your schema clean. Use @uninstall.sql too if you want the CAP_* objects gone as well.

SQL*Plus · captest@pdb1you run
SQL> @test/fixture_remove.sql
SQL> @uninstall.sql
▸

One-shot version. To run the whole self-check non-interactively over SSH, feed the same sequence to a heredoc: sqlplus -S -L captest/<password>@localhost:1521/pdb1.world <<'SQL' containing @test/fixture_install.sql · DEFINE seam_mode=fixture · @install.sql · @test/run_test.sql · @test/run_test_ml.sql. Both test scripts exit non-zero on failure, so the SSH command's exit status is your pass/fail signal.

Walkthrough · Track B

Local smoke on cdb1

The same analytics, now against your live AWR. This confirms the suite installs and reports end-to-end on a real 19c CDB.

1

Connect as sysdba in CDB$ROOT

AWR lives at the root container, so local mode installs there. (Repo already synced from Track A step 1 — re-sync if you've edited since.)

test box · bashyou run
ssh -p <port> oracle@<host>
export ORACLE_SID=cdb1; export ORAENV_ASK=NO; . oraenv >/dev/null 2>&1
cd ~/awr_capacity_predictions
sqlplus / as sysdba
2

Check you have Diagnostics Pack

Local mode reads DBA_HIST_*, which requires the pack. A monitoring schema (not sysdba) would also need direct SELECT grants on those views — not via a role — for the views to compile.

SQL*Plus · sys@CDB$ROOTyou run
SQL> SHOW PARAMETER control_management_pack_access
outputexpect
NAME                               TYPE     VALUE
---------------------------------- -------- ------------------
control_management_pack_access     string   DIAGNOSTIC+TUNING
3

Install in local mode

SQL*Plus · sys@CDB$ROOTyou run
SQL> DEFINE seam_mode = 'local'
SQL> @install.sql

Same layered output as Track A, ending in All CAP* objects valid. If any view is invalid, the closing check aborts with the exact grant/pack hint.

4

Run the report

SQL*Plus · sys@CDB$ROOTyou run
SQL> @report/defaults.sql
SQL> @report/report.sql
!

Expect INSUFFICIENT_HISTORY on a stock box. Default AWR retention is only 8 days — far below the 90-day training window — so forecasts degrade loudly and say so. That's correct behavior, not a bug. Watch the TRAIN_N and QUALITY columns.

5

For real trends, raise retention — then wait

This only helps future snapshots; history isn't backfilled, so you'll see real forecasts only after enough days accumulate.

SQL*Plus · sys@CDB$ROOTyou run
SQL> EXEC DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS(retention => 90*24*60);
i

This changes a database setting. It's a persistent AWR configuration change on the CDB (harmless on a test box, but not read-only). Run it deliberately.

6

Optionally train Tier 2, then pull the report home

Once you have history, add the ESM second opinion and re-run the report to populate section 6. Then copy the spooled file back to read it.

SQL*Plus · sys@CDB$ROOTyou run
SQL> EXEC cap_forecast_ml.train_all(20);   -- top-20 tablespaces + CPU
SQL> @report/report.sql
workstation · bashyou run
rsync -az -e 'ssh -p <port>' \
  oracle@<host>:~/awr_capacity_predictions/reports/ ./reports/

For how to read the six sections of the report output, see Usage · Reading the report.
