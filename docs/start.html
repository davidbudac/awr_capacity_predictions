Getting started

Clone it, run one command, read the report

Nothing to download beyond this repository, nothing to configure, nothing written to your AWR data. One script runs the preflight, installs the views and prints your first capacity report.

i

You need three things. An Oracle Database 19c or newer with the Diagnostics Pack (that is where AWR comes from), a sqlplus that can reach it, and a connection as sysdba to CDB$ROOT, because that is where AWR history lives. Anything else is optional and covered under Advanced install.

Three steps

From zero to a report

About five minutes, most of it waiting for the views to compile.

1

Get the code where sqlplus is

The database host is the easiest place: sqlplus is already there and / as sysdba just works.

DB host · bashyou run
git clone https://github.com/davidbudac/awr_capacity_predictions.git
cd awr_capacity_predictions
2

Run the quickstart

One command. It runs the read-only preflight, installs every object into the current schema and spools your first report. Safe to re-run at any time.

DB host · bashyou run
./quickstart.sh                    # connects as / as sysdba

No shell, or connecting from elsewhere? The same thing from inside SQL*Plus, started in the repository directory:

SQL*Plus · CDB$ROOTalternative
sqlplus / as sysdba
SQL> @quickstart.sql

The tail of the output tells you it worked and where the report went:

outputexpect
  All CAP* objects valid.
============================================================
 Install complete (seam_mode = local).
============================================================
...
Report written to: reports/cap_report_CDB1_202609221410.txt
3

Read the report

Plain text, eight sections, top to bottom: days-to-full per tablespace, growth forecasts, anomalies, CPU trend, then the fixed-ceiling series. The first lines say in plain English whether anything is heading for trouble.

DB host · bashyou run
less reports/cap_report_*.txt

Want to know what you are looking at before you run it? Open the sample HTML report (or its text twin): the real output of both drivers against a fictional e-commerce database with 150 days of designed history. From here on, a report is just @report/report.sql from the repository directory, and Usage explains every section.

!

First report says INSUFFICIENT_HISTORY? That is expected. Stock AWR keeps only 8 days of history and a forecast needs at least 14 daily points, so on a fresh database the suite refuses to project a trend it cannot see yet. Nothing is broken. Raise retention once and the forecasts fill in over the following weeks. This is the only change to Oracle anywhere in this guide, and it is optional.

SQL*Plus · CDB$ROOToptional · once
SQL> EXEC DBMS_WORKLOAD_REPOSITORY.MODIFY_SNAPSHOT_SETTINGS(retention => 90*24*60);  -- 90 days
Under the hood

What the quickstart just did

Three existing scripts in a row, nothing more. You can run each on its own later.

quickstart.sql, step by step
StepScriptDoes
1doctor.sqlRead-only preflight: Diagnostics Pack, DBA_HIST_* grants, privileges, AWR retention and how much history each source holds. Prints a PASS / WARN / FAIL checklist and explains any gap.
2install.sqlCreates the views, three small config tables and the Tier 2 package in the current schema, in local mode. Idempotent; re-running never overwrites a knob you changed. Fails loudly if any object is invalid.
3report/report.sqlThe read-only text report, spooled to reports/.
▸

Read-only against AWR, always. The only rows the suite ever writes are in its own CAP_CONFIG, CAP_TBSPC_OVERRIDE and CAP_ML_MODEL tables. Remove everything again with @uninstall.sql.
